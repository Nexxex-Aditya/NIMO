# specs/scaffold.md — P0: Repo Scaffold

Authority: `04-build-standards.md` §1 (P0), §2 (layout). Read those first; this
spec is the literal instruction for filling them in. Nothing in this phase
touches pipeline logic — no fetching, no parsing, no LLM calls. Scope
violation (writing any `src/nimo/<module>/` logic beyond an empty `__init__.py`)
is an escalation per `04` §13, not a judgement call.

## Precondition — check the repo before assuming this is a manual step

`data/raw/product_truth_agent_dataset.xlsx` needs to exist at that exact
path — **check first whether it's already committed somewhere else in the
repo** (observed once: committed at `Project_info/product_truth_agent_dataset.xlsx`
instead of `data/raw/`). If it's elsewhere in the repo, `git mv` it to the
canonical path — don't copy, and don't leave two copies; `04` §2 designates
`data/raw/` as the one read-only source of truth. Only if the file isn't in
the repo at all does this become a genuine manual step: it lives in the
project workspace this design was authored in, and in that case
must be placed by hand — **do not attempt to fetch, generate, or fabricate
it.** If it's absent from the whole repo when this phase runs, create the
directory and proceed — loading it is P2's job, not this one — but flag its
absence rather than silently skipping the directory.

## `pyproject.toml`

Full dependency set declared now, in one pass, rather than re-touching this
file at every later phase. Comment marks which phase actually exercises each
group — a dependency being present doesn't mean it's used yet.

**This exact content was verified end-to-end** — `uv sync`, `ruff check`,
`ruff format --check`, `mypy --strict`, `uv run pytest`, all four exit 0 —
against `uv 0.11.7`, `ruff 0.16.6`, `mypy 2.3.1`. An earlier version of this
file was not verified and failed on all three counts when actually run
(`02-decision-log.md` has the full record); this version fixes all three.

```toml
[project]
name = "nimo"
version = "0.1.0"
requires-python = ">=3.12,<3.13"
dependencies = [
    "pydantic>=2.6",
    "pydantic-settings>=2.2",   # P0 — typed, validated env/config loading
    "pyyaml>=6.0",              # P0 — config/*.yaml
    "structlog>=24.1",          # P0 — structured JSON logs, `04` §10
    "pandas>=2.2",              # P2 — loader
    "openpyxl>=3.1",            # P2 — loader; also direct cell access for EXTERNAL_CODE
    "ftfy>=6.2",                # P2 — encoding-corruption repair, `01` §13
    "httpx>=0.27",              # P7/P8 — retrieval, fetch
    "tenacity>=8.2",            # P8 — retry with backoff+jitter, `04` §6
    "trafilatura>=1.8",         # P8 — boilerplate-stripped body text
    "extruct>=0.18",            # P8 — JSON-LD / microdata / OpenGraph extraction
    "rapidfuzz>=3.6",           # P9 — Layer A text-similarity features
]
# LLM client deliberately NOT declared yet — provider/SDK depends on Q7
# (02-decision-log.md open questions). Add when that resolves, scoped to P11.

[build-system]
requires = ["uv_build>=0.11,<0.12"]
build-backend = "uv_build"
# Without this table, uv treats the project as virtual (non-packaged) and
# never installs `nimo` into the venv — `import nimo` then fails everywhere,
# including test collection. uv_build over hatchling/setuptools: this project
# already commits to uv for everything else (04 §2, §9), and uv_build needs
# no config beyond this given `src/nimo` already matches `[project].name`.

[dependency-groups]
dev = [
    "ruff>=0.4",
    "mypy>=1.10",
    "pytest>=8.1",
]

[tool.ruff]
target-version = "py312"
line-length = 100
extend-exclude = ["docs", "specs"]
# Without this, `ruff format` reformats Python code blocks embedded in
# Markdown — verified against ruff 0.16.6: it rewrote illustrative snippets
# in docs/03-architecture.md and specs/*.md, corrupting hand-aligned comments
# in the design authority itself. This exclude is defense in depth; the
# Makefile below also scopes its targets to `src`/`tests` directly, which is
# the primary fix — keep both, don't rely on either alone.

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]

[tool.mypy]
python_version = "3.12"
strict = true
warn_unused_ignores = true
plugins = ["pydantic.mypy"]
# Required, not optional — without this, mypy --strict sees pydantic's
# runtime-generated __init__ incorrectly and rejects zero-argument
# construction of a BaseSettings/BaseModel subclass whose fields are meant to
# populate from the environment or from validation defaults. Verified this
# breaks settings.py's fail-fast pattern (04 §9) without the plugin, and
# verified separately that a frozen BaseModel with inheritance — the exact
# shape P1's contracts use (RawRow / ProductQuery(RawRow)) — also needs it.
# This is a project-wide type-checking posture decision, made once here,
# before P1 exists, specifically so P1 doesn't hit the same class of failure
# and have to re-litigate it.

# Third-party libraries without type stubs. This is the sanctioned place for
# that gap — never a per-line `# type: ignore` scattered through logic (`04`
# §3, §12). Add an entry here only when mypy actually reports the import as
# untyped; don't pre-emptively silence a package that turns out to have stubs.
[[tool.mypy.overrides]]
module = ["extruct.*", "trafilatura.*"]
ignore_missing_imports = true

[tool.pytest.ini_options]
testpaths = ["tests"]
```

Run `uv lock` after writing this to generate `uv.lock`; commit both.

## `Makefile`

**Scoped to `src`/`tests`, not `.`** — this is the primary fix for the
Markdown-reformatting issue above; the `extend-exclude` in `pyproject.toml`
is the backup, not the other way around.

```makefile
.PHONY: check fmt

check:
	uv run ruff check src tests
	uv run ruff format --check src tests
	uv run mypy --strict src tests
	uv run pytest

fmt:
	uv run ruff format src tests
	uv run ruff check --fix src tests
```

`make check` is the P0 gate and every later phase's DoD item (`04` §11). It
must exit non-zero on any failure — no target may swallow a subcommand's exit
code.

**If `make` itself isn't available on the machine** (observed: absent on a
Windows/Git Bash setup with no `make`/`mingw32-make`/`gnumake`/`nmake`), run
the four `check` commands above directly, in this order, and record each
exit code separately — that's a full, valid gate verification, not a
workaround. The committed `Makefile` remains the real gate in CI
(`.github/workflows/check.yml` runs on `ubuntu-latest`, where `make` is
present) and stays unaffected either way.

## `src/nimo/settings.py`

`pydantic-settings`-based, validated at import time — fails immediately on a
missing required variable, not at first use (`04` §9). Skeleton for P0; fields
grow as later phases need them, but the fail-fast pattern is established now:

```python
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    searxng_base_url: str
    log_level: str = "INFO"


settings = Settings()  # raises at import time if a required var is absent
```

## `src/nimo/logging.py`

`structlog`, JSON renderer, one shared configuration function called once at
process start (by `run/`, later). No module reaches for the stdlib `logging`
module directly or calls `print()` (`04` §10, `04` §12 forbidden patterns).

```python
import logging

import structlog


def configure_logging(level: str = "INFO") -> None:
    logging.basicConfig(format="%(message)s", level=level)
    structlog.configure(
        processors=[
            structlog.processors.TimeStamper(fmt="iso"),
            structlog.processors.add_log_level,
            structlog.processors.JSONRenderer(),
        ],
        wrapper_class=structlog.make_filtering_bound_logger(logging.getLevelName(level)),
    )
```

## `config/*.yaml` — stubs, not filled in

These files exist with schema and a couple of illustrative entries so later
phases have a place to write into, not a full population — that's real
research work belonging to the phase that needs it (`04` §1).

`config/retailers.yaml` — schema is `retailer_raw_string: {name, domain}`, not
a flat string→string map (revised from an earlier draft — see
`02-decision-log.md`). **`name` is a P2 precondition, not P7** — `name`
entries for all 50 distinct `retailer_raw` values (`01` §9 — not ~44, that
was a `dev`-only count) must exist before `specs/loader.md` is done, because
loader §4 looks up retailer names from this table rather than parsing them
with a regex (a regex was tried and measured at a 42% failure rate against
the real 50 values, one case silently — `01` §12). `domain` can stay
partially populated until P7. Two entries seeded here as an example of the
shape, including the case that broke the regex:

```yaml
# retailer_raw (exact RETAILER column value) -> {name, domain}
```

## Acceptance criteria (P0 gate)

1. `make check` exits 0 on this scaffold with no other code written — or, if
   `make` isn't available locally, its four commands each exit 0 when run
   directly (see Makefile section above).
2. `uv run pytest` collects and passes exactly one test.
3. Every directory in the tree above exists, including empty ones — verify
   with `find src/nimo -type d` matching the module list.
4. `data/registry/`, `data/raw/`, `data/gold/` are **not** matched by
   `.gitignore` (`git check-ignore` returns nothing for a test file placed in
   each); `data/cache/` and `data/out/` **are**.
5. `python -c "from nimo.settings import settings"` raises a clear
   `pydantic_core.ValidationError` when `.env` is absent and
   `SEARXNG_BASE_URL` is unset — proving fail-fast actually fires, not just
   that the class compiles.
6. No file under `src/nimo/*/` other than `contracts.py`, `settings.py`,
   `logging.py`, and `__init__.py` files contains any code.
